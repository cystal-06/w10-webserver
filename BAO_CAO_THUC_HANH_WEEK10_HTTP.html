1. Gửi HTTP Request thủ công qua Telnet

Mục tiêu: Kết nối trực tiếp đến Web Server trên cổng TCP 80, tự tay soạn thảo bản tin HTTP/1.0 Request và phân tích cấu trúc phản hồi HTTP Response.

Lệnh kết nối:

telnet www.google.com 80

Soạn nội dung Request (gõ trực tiếp vào terminal):

GET / HTTP/1.0
If-Modified-Since: Thu, 29 Oct 2026 00:00:00 GMT
User-Agent: NguyenCongDuc-24SE1-24IT340

(Chú ý: Sau dòng User-Agent, nhấn phím Enter 2 lần để báo hiệu kết thúc phần HTTP Header).

Phân tích thành phần bản tin HTTP Request:

Thành phần Giá trị thực tế Ý nghĩa kỹ thuật
Request Method GET Phương thức yêu cầu tài nguyên từ máy chủ
URI / Tài nguyên gốc (Root document)
Protocol Version HTTP/1.0 Phiên bản giao thức HTTP sử dụng
Request Modifiers If-Modified-Since: Thu, 29 Oct 2026 00:00:00 GMT Header điều kiện: chỉ tải trang nếu có sửa đổi sau thời điểm này
Client Information User-Agent: NguyenCongDuc-24SE1-24IT340 Định danh thông tin client gửi yêu cầu (tên và MSSV sinh viên)

Phân tích thành phần bản tin HTTP Response nhận được:

Thành phần Response Giá trị ghi nhận Giải thích
Status Line HTTP/1.0 200 OK Thực thi thành công, tài nguyên hợp lệ
Server Information Server: gws Web server Google (Google Web Server)
Entity Meta-Information Content-Type: text/html; charset=ISO-8859-1
Date: Thu, 29 Oct 2026 ...		 Định dạng tài nguyên trả về là HTML và thời gian phản hồi theo chuẩn GMT
Content Body <!doctype html>... Mã nguồn HTML trang chủ Google

2. Khảo sát các nhóm Status Code trong HTTP

2.1. Phản hồi chuyển hướng Redirect 301 (Nhóm 3xx)

Mục tiêu: Kiểm tra hành vi chuyển hướng khi truy cập vào cổng HTTP không mã hóa của máy chủ yêu cầu HTTPS.

Lệnh kết nối:

telnet www.stevens.edu 80

Nội dung Request:

GET / HTTP/1.1
Host: www.stevens.edu

Kết quả phân tích: Server trả về mã HTTP/1.1 301 Moved Permanently kèm tiêu đề Location: https://www.stevens.edu/ thông báo trang web đã chuyển sang giao thức bảo mật HTTPS.

[CHÈN ẢNH CHỤP TERMINAL 2 TẠI ĐÂY]
(Chụp kết quả trả về mã 301 Moved Permanently và trường Location)
Hình 2: Phản hồi mã trạng thái 301 Moved Permanently từ máy chủ Stevens Institute

2.2. Kết nối HTTPS bằng OpenSSL s_client (Nhóm 2xx)

Mục tiêu: Thiết lập phiên kết nối TLS/SSL bảo mật qua cổng 443 và kiểm tra mã thành công 200 OK.

Lệnh kết nối:

openssl s_client -servername www.stevens.edu -connect www.stevens.edu:443

Gửi Request sau khi bắt tay TLS hoàn tất:

GET / HTTP/1.1
Host: www.stevens.edu

Kết quả: Sau quá trình trao đổi chứng chỉ bảo mật (Certificate Verification), gửi request HTTP/1.1 nhận được phản hồi HTTP/1.1 200 OK với Server: cloudflare.

[CHÈN ẢNH CHỤP TERMINAL 3 TẠI ĐÂY]
(Chụp kết quả bắt tay TLS thành công và phản hồi HTTP/1.1 200 OK)
Hình 3: Kết nối bảo mật HTTPS qua openssl s_client nhận trạng thái 200 OK

2.3. Bảng tổng hợp phân loại mã trạng thái HTTP

Nhóm mã Tên phân loại Ý nghĩa Ví dụ điển hình
1xx Informational Yêu cầu đã được tiếp nhận, đang tiếp tục xử lý 100 Continue
2xx Success Yêu cầu đã được nhận, hiểu và chấp thuận thành công 200 OK, 204 No Content
3xx Redirection Cần hành động chuyển tiếp để hoàn thành yêu cầu 301 Moved Permanently, 304 Not Modified
4xx Client Error Lỗi do phía client (sai cú pháp hoặc không hợp lệ) 400 Bad Request, 403 Forbidden, 404 Not Found
5xx Server Error Lỗi từ phía máy chủ khi cố gắng thực thi yêu cầu 500 Internal Server Error, 502 Bad Gateway

3. Khảo sát cơ chế Transfer Protocol và CGI

3.1. Thương lượng định dạng tài nguyên với header Accept

Mục tiêu: Quan sát cơ chế Content Negotiation khi client chỉ định loại nội dung mong muốn nhận từ server.

Lệnh kết nối:

telnet www.google.com 80

Nội dung Request:

GET / HTTP/1.0
Accept: application/json
User-Agent: NguyenCongDuc-24IT340

Phân tích: Client gửi thông điệp yêu cầu định dạng JSON (Accept: application/json). Server xem xét khả năng đáp ứng và trả về định dạng phù hợp nhất qua tiêu đề Content-Type.

[CHÈN ẢNH CHỤP TERMINAL 4 TẠI ĐÂY]
(Chụp request có chứa header Accept: application/json và User-Agent của sinh viên)
Hình 4: Cơ chế thương lượng nội dung thông qua trường tiêu đề Accept

3.2. Kiểm tra thực thi kịch bản CGI (Common Gateway Interface)

Mục tiêu: Thực thi một tài nguyên động phía máy chủ (Server-side dynamic resource) và phân tích các biến môi trường được truyền qua CGI.

Lệnh kiểm tra:

curl -v https://www.netmeister.org/cgi-bin/env.cgi

Phân tích kết quả: Kịch bản env.cgi trên máy chủ được thực thi theo chuẩn RFC 3875, tự động trích xuất các thông tin kết nối và trả về danh sách biến môi trường HTTP (như REQUEST_METHOD=GET, REMOTE_ADDR, HTTP_USER_AGENT, SERVER_PROTOCOL=HTTP/2).

4. So sánh thực nghiệm giữa HTTP/1.0 và HTTP/1.1

Mục tiêu: Sử dụng công cụ curl để gửi yêu cầu lấy tiêu đề (HEAD request) theo cả hai phiên bản giao thức và đối chiếu sự khác biệt.

Lệnh thực nghiệm:

# Kiểm tra phiên bản HTTP/1.0:
curl -I --http1.0 https://www.google.com

# Kiểm tra phiên bản HTTP/1.1:
curl -I --http1.1 https://www.google.com

Bảng đối chiếu đặc tính kỹ thuật giữa HTTP/1.0 và HTTP/1.1:

Tiêu chí HTTP/1.0 (RFC 1945) HTTP/1.1 (RFC 2616 / RFC 7230)
Kết nối TCP (Connection) Đóng kết nối sau mỗi request (Non-persistent). Mỗi tài nguyên mở 1 kết nối mới. Mặc định duy trì kết nối (Persistent Connection - Keep-Alive), hỗ trợ Pipelining.
Tiêu đề Host Không bắt buộc (gây khó khăn cho cơ chế máy chủ ảo Virtual Hosting). Bắt buộc phải có trường Host: trong mọi request.
Truyền dữ liệu (Transfer) Dựa vào Content-Length cố định. Hỗ trợ Transfer-Encoding: chunked (truyền theo từng khối linh hoạt).
Cơ chế Cache Cơ bản thông qua If-Modified-Since, Expires. Mở rộng mạnh mẽ với Cache-Control, ETag, If-None-Match.

Hình 6: So sánh tiêu đề phản hồi thực tế giữa giao thức HTTP/1.0 và HTTP/1.1
